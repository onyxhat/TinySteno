## Diarization: how speakers are separated and labelled

### Takeaway
anarlog layers four mechanisms: (1) channel separation (mic = channel 0, system audio = channel 1, recorded as stereo, with neural echo cancellation on the mic when playing through speakers); (2) within-channel diarization, either from the cloud STT provider or from an on-device pyannote-3.1-style pipeline (segmentation-3.0 powerset model + WeSpeaker embeddings + centroid-linkage agglomerative clustering) written in Rust on ONNX Runtime; (3) persistent on-device voiceprints that merge fragmented clusters and name speakers; (4) identity rules that map channels/speakers to calendar participants, plus manual assignment. Local diarization is post-hoc (after recording); live speaker labels come from the cloud provider or from channel identity.

Echo cancellation and mic/speaker bleed
- AEC is enabled unless the output device is headphones or `NO_AEC=1`: `enable_aec: !no_aec_override && !headphone_output`; `mic_isolated: headphone_output && !mic_swapped`. It is toggled at runtime when the output device changes. — [crates/listener-core/src/actors/source/stream.rs L59-L76](https://github.com/fastrepl/anarlog/blob/a99e237/crates/listener-core/src/actors/source/stream.rs)
- AEC is a two-stage ONNX model pair (`model_{128,256,512}_1.onnx` and `_2.onnx`, default feature `128`), block size 512 / shift 128, operating with FFT masking then a second fused model, with streaming state. The loopback reference is time-aligned to the mic by an `AecReferenceAligner`, and a smoothed `linear_echo_gain` residual canceller runs after the network (`cancel_linear_echo`). — [crates/aec/src/onnx/model.rs](https://github.com/fastrepl/anarlog/blob/a99e237/crates/aec/src/onnx/model.rs), [crates/aec/src/onnx/mod.rs L203-L330](https://github.com/fastrepl/anarlog/blob/a99e237/crates/aec/src/onnx/mod.rs), [crates/audio-actual/src/capture/stream.rs L213-L324, L659-L731](https://github.com/fastrepl/anarlog/blob/a99e237/crates/audio-actual/src/capture/stream.rs)
- The local live path (Soniqo) adds an "echo gate": `suppress_echo_dominant_mic(mic, speaker)` zeroes a mic chunk that is dominated by the speaker signal, using cross-correlation over lags up to 1600 samples (constants `ECHO_GATE_MIN_CORRELATION = 0.55`, `ECHO_GATE_MAX_RESIDUAL_RATIO = 0.45`; tests named `suppresses_mic_when_aec_residual_has_longer_capture_lag`). — [crates/owhisper-client/src/local_soniqo_live.rs L11-L18, L429-L481](https://github.com/fastrepl/anarlog/blob/a99e237/crates/owhisper-client/src/local_soniqo_live.rs)
- Speaker-side track sent to the recogniser is always `raw_speaker`; the mic track is `frame.capture.preferred_mic()` (zeros when muted). — [crates/listener-core/src/actors/source/pipeline.rs L255-L271](https://github.com/fastrepl/anarlog/blob/a99e237/crates/listener-core/src/actors/source/pipeline.rs)

On-device diarization pipeline (`crates/pyannote-local`)
- Module doc (verbatim): "Offline speaker diarization: sliding-window segmentation, masked speaker embeddings, agglomerative clustering, then reconstruction of who spoke when. Mirrors the structure of the pyannote.audio 3.1 pipeline, tuned for CPU batch use after a recording ends." — [crates/pyannote-local/src/pipeline.rs L1-L4](https://github.com/fastrepl/anarlog/blob/a99e237/crates/pyannote-local/src/pipeline.rs)
- Segmentation: a bundled 6 MB `segmentation.onnx`; 16 kHz, fixed 10 s windows, 270-sample frames, at most 3 local speakers per window; comment "segmentation-3.0 predicts a powerset over three local speakers, ordered by cardinality: silence, the three singletons, then the three pairs" (so overlapped speech of up to two simultaneous speakers is modelled). — [crates/pyannote-local/src/segmentation.rs L6-L28](https://github.com/fastrepl/anarlog/blob/a99e237/crates/pyannote-local/src/segmentation.rs)
- Embeddings: bundled 26.5 MB `embedding.onnx` fed kaldi fbank features (`knf-rs`), with a config comment "Matches pyannote.audio's ONNXWeSpeakerPretrainedSpeakerEmbedding implementation"; the voiceprint store labels the model `MODEL_PROVIDER = "pyannote"`, `MODEL_VERSION = "wespeaker-embedding-onnx-1"`. — [crates/embedding/src/onnx/mod.rs L12-L27](https://github.com/fastrepl/anarlog/blob/a99e237/crates/embedding/src/onnx/mod.rs), [plugins/transcription/src/voiceprint.rs L13-L14](https://github.com/fastrepl/anarlog/blob/a99e237/plugins/transcription/src/voiceprint.rs)
- Defaults (`DiarizationConfig::default`): `step_seconds: 2.0` ("2 s keeps every frame under ~5 overlapping windows so majority voting suppresses per-window false speech"), `min_embedding_seconds: 1.0` of clean (non-overlapped) speech before an embedding is a clustering anchor, `min_activity_seconds: 0.3`, `clustering_threshold: 0.7045` (centroid linkage, euclidean on unit-normalised embeddings), `min_cluster_seconds: 12.0` ("pyannote's 12 anchors at a 1 s step"), `max_windows: 1800` (step grows on long recordings "so compute stays bounded"), `known_speaker_min_score: MIN_UNIQUE_SCORE` (0.62). — [crates/pyannote-local/src/pipeline.rs L17-L62](https://github.com/fastrepl/anarlog/blob/a99e237/crates/pyannote-local/src/pipeline.rs), [crates/voiceprint/src/matching.rs L3-L4](https://github.com/fastrepl/anarlog/blob/a99e237/crates/voiceprint/src/matching.rs)
- Main loop (`Diarizer::diarize`): per window run segmentation, for each local speaker with enough activity compute a masked embedding (clean-only mask if it qualifies as an anchor), then `cluster` -> `apply_known_speakers` -> `reconstruct` (per-frame majority vote across overlapping windows) -> `renumber_by_first_appearance`. Supports cancellation and a progress callback; audio is read through a random-access `AudioSource` trait so long WAVs need not be in memory. — [crates/pyannote-local/src/pipeline.rs L105-L268, L447-L450](https://github.com/fastrepl/anarlog/blob/a99e237/crates/pyannote-local/src/pipeline.rs)
- Clustering: "centroid-linkage recipe used by pyannote.audio 3.1 ... the dendrogram is cut at a fixed threshold, and clusters smaller than `min_cluster_size` are absorbed by the nearest large cluster"; `SpeakerBounds` (exact / min / max) overrides the threshold cut by choosing "the cut whose large-cluster count is closest to the bounds". — [crates/pyannote-local/src/clustering.rs L1-L5, L238-L266](https://github.com/fastrepl/anarlog/blob/a99e237/crates/pyannote-local/src/clustering.rs)
- Word assignment: `assign_words` gives each word "the speaker with the largest overlap, falling back to the nearest turn when the word lies in a gap". — [crates/pyannote-local/src/pipeline.rs L603-L606](https://github.com/fastrepl/anarlog/blob/a99e237/crates/pyannote-local/src/pipeline.rs)
- Hardware acceleration: Cargo features `coreml` and `directml` on the ONNX and embedding crates; the batch code mentions "an accelerator cache rebuild, which is a full recompile of both" models. — [crates/pyannote-local/Cargo.toml](https://github.com/fastrepl/anarlog/blob/a99e237/crates/pyannote-local/Cargo.toml), [crates/listener2-core/src/batch/diarize.rs L500-L502](https://github.com/fastrepl/anarlog/blob/a99e237/crates/listener2-core/src/batch/diarize.rs)
- Evaluation harness: an eval binary computes DER (collar 0.25 s) on AMI and VoxConverse dev/test sets; the documented "autoresearch loop" keeps a change only if "DER improved by more than 0.1 absolute points and `rtf` stayed under 0.15 on the reference machine". — [crates/pyannote-local/eval/PROGRAM.md](https://github.com/fastrepl/anarlog/blob/a99e237/crates/pyannote-local/eval/PROGRAM.md)
- Introduced in desktop 1.4.17 (2026-09-03): "Separate speakers during on-device batch transcription, with more resilient diarization and automatic recovery from damaged Core ML model caches". — [packages/changelog/content/desktop/1.4.17.md](https://github.com/fastrepl/anarlog/blob/a99e237/packages/changelog/content/desktop/1.4.17.md)

How the batch pipeline decides which channel to diarize
- Stereo call: the direct-mic channel "of a call is never diarized"; the remote channel is diarized with bound = participants minus one; "A 1:1 call has a single remote voice: nothing to separate" (skipped). — [crates/listener2-core/src/batch/diarize.rs L74-L81, tests L720-L802](https://github.com/fastrepl/anarlog/blob/a99e237/crates/listener2-core/src/batch/diarize.rs)
- In-person detection: "the session expected several participants, yet the system-audio channel stayed silent, so they were all in the room sharing the microphone"; then the mic channel is diarized with the full participant count and its words move to a shared channel so "The renderer names its speakers instead of folding them into 'You'". — [crates/listener2-core/src/batch/diarize.rs L27-L32, L117-L122](https://github.com/fastrepl/anarlog/blob/a99e237/crates/listener2-core/src/batch/diarize.rs)
- Providers that downmix stereo (comment: "Whisper/Argmax collapse a stereo capture into one transcript channel") are diarized on the averaged mix with the full participant count (`MixedAudioSource` "read in lockstep and averaged"). — [crates/listener2-core/src/batch/diarize.rs L63-L72, L597-L598, tests L760-L769](https://github.com/fastrepl/anarlog/blob/a99e237/crates/listener2-core/src/batch/diarize.rs)
- Diarization emits progress heartbeats because progressive sessions are torn down after 60 s of silence, and only word timings cross into the blocking task "so a panic in the diarizer cannot lose" the transcript. — [crates/listener2-core/src/batch/diarize.rs L33-L35, L251-L254, L419-L423](https://github.com/fastrepl/anarlog/blob/a99e237/crates/listener2-core/src/batch/diarize.rs)

Cloud-provider diarization and its consolidation
- Live listen params: `num_speakers` and `max_speakers` are left unset because `expected_speakers_per_channel` returns `None` with the comment "Calendar attendance is not an upper bound on the voices in a recording"; `mic_num_speakers` is 1 only when the mic is isolated (headphones). — [crates/listener-core/src/actors/listener/adapters.rs L489-L513](https://github.com/fastrepl/anarlog/blob/a99e237/crates/listener-core/src/actors/listener/adapters.rs), [crates/listener-core/src/lib.rs L37-L43](https://github.com/fastrepl/anarlog/blob/a99e237/crates/listener-core/src/lib.rs)
- Docs claim: "For stereo recordings, Soniox combines the microphone and computer-audio channels and uses speaker diarization to distinguish speakers." Managed cloud prefers Soniox 5 (`stt-rt-v5` / `stt-async-v5`), with Deepgram Nova 3/2, AssemblyAI Universal 3.5 Pro, Gladia, ElevenLabs, OpenAI, Mistral, Alibaba as fallbacks. — [docs/models-and-providers.mdx](https://github.com/fastrepl/anarlog/blob/a99e237/docs/models-and-providers.mdx)
- Hosted batch post-pass (module doc, verbatim): "Cloud providers label speakers but never see the session's participant count or voiceprints (Soniox and Deepgram have no speaker-count parameter, and biometrics stay on device), so a remote channel often comes back with more 'speakers' than people. Voiceprints and speaker naming
- Span selection: from transcript words, pick up to 3 clean spans per (channel, speaker), 1.5-10 s each, merging gaps <= 400 ms and cutting out regions where two speakers overlap on a channel ("overlapped speech contaminates embeddings"). — [crates/voiceprint/src/lib.rs L36-L66](https://github.com/fastrepl/anarlog/blob/a99e237/crates/voiceprint/src/lib.rs)
- Matching is conservative: `MIN_UNIQUE_SCORE = 0.62` cosine and `MIN_UNIQUE_MARGIN = 0.08`, mutual-unique assignment (tests: `does_not_guess_when_two_speakers_want_the_same_person`, `does_not_guess_when_the_margin_is_thin`); `complete_by_elimination` names the last speaker only when "The count must match exactly: a no-show or an uninvited guest breaks the inference, so nothing is guessed." — [crates/voiceprint/src/matching.rs L3-L4, L139-L143](https://github.com/fastrepl/anarlog/blob/a99e237/crates/voiceprint/src/matching.rs)
- Enrolment lifecycle: embeddings are stored as candidates (TTL 45 days) and promoted to exemplars on confirmation; with headphone output "the direct-mic channel can only carry the session owner, so its candidates are confirmed self exemplars without waiting for a manual speaker assignment" (confidence 0.9); "1:1 meetings are named from the participant list. Voiceprints only identify people when the calendar cannot uniquely name the remotes." Voiceprints are "consulted on device ... never sent to a provider". — [plugins/transcription/src/voiceprint.rs L15-L22, L289, L411-L414, L939-L940](https://github.com/fastrepl/anarlog/blob/a99e237/plugins/transcription/src/voiceprint.rs), [crates/listener2-core/src/batch/mod.rs L133-L135](https://github.com/fastrepl/anarlog/blob/a99e237/crates/listener2-core/src/batch/mod.rs)
- In the diarizer, known voiceprints "steer the result in two ways: clusters whose best match is the same known voice are merged (fragmentation of one voice is the most common local-diarization failure), and the survivors are named when the match is unique on both sides." — [crates/pyannote-local/src/pipeline.rs L331-L334](https://github.com/fastrepl/anarlog/blob/a99e237/crates/pyannote-local/src/pipeline.rs)
- Label rendering: a known human id renders as the contact name; the direct mic renders as the user's name or "You"; unknowns render as "Speaker N" numbered by first appearance (optionally capped). — [crates/transcript/src/label.rs L81-L120](https://github.com/fastrepl/anarlog/blob/a99e237/crates/transcript/src/label.rs)
- Owner-voice rule on a non-isolated mic: "A room mic on a call also catches nearby chatter and diarization splits of the owner's own voice, so the voice carrying at least this share of the interval's mic words is the owner" (`OWNER_VOICE_SHARE_PERCENT = 80`); "The far end of a call is whoever else was invited, regardless of how many voices diarization reports for it." — [crates/transcript/src/speaker_context.rs L206-L260](https://github.com/fastrepl/anarlog/blob/a99e237/crates/transcript/src/speaker_context.rs)
- Manual assignment (changelog claims): "Apply a speaker name across a meeting without changing unrelated speakers, and preserve assignments through transcript refinement" (1.4.24); "Label the other person in a 1:1 transcript, and name speakers in larger meetings only when a unique high-confidence voiceprint match is available" (1.4.14). Code keeps user assignments across re-transcription via thresholds `MIN_REFINED_SPEAKER_OVERLAP_RATIO = 0.6`, `MIN_REFINED_ASSIGNMENT_COVERAGE_RATIO = 0.8`. — [packages/changelog/content/desktop/1.4.24.md](https://github.com/fastrepl/anarlog/blob/a99e237/packages/changelog/content/desktop/1.4.24.md), [packages/changelog/content/desktop/1.4.14.md](https://github.com/fastrepl/anarlog/blob/a99e237/packages/changelog/content/desktop/1.4.14.md), [crates/transcript/src/batch_refine.rs L14-L17](https://github.com/fastrepl/anarlog/blob/a99e237/crates/transcript/src/batch_refine.rs)

### Inferences
- (Inference) The AEC network is a DTLN-aec-style model: two ONNX stages, 512/128 block/shift, FFT-magnitude masking then a time-domain second stage, in three state sizes (128/256/512). The file names and processing structure match that architecture, but the crate does not name it.
- (Inference) `Community1DiarizationPipeline` in speech-swift is presumably a CoreML port of pyannote's "community-1" diarization pipeline; the name suggests it, the anarlog repo does not document it.
- (Inference) `preferred_mic()` presumably returns the echo-cancelled mic when AEC is active and the raw mic otherwise; I did not read its definition.
- (Inference) Local diarization is strictly post-hoc: the `pyannote-local` doc says "tuned for CPU batch use after a recording ends", and local live transcription relies on channel identity ("You" vs remote) plus later refinement. Live multi-speaker labels on the remote channel are available only from cloud providers that diarize in streaming mode (e.g. Soniox).
- (Inference) The 12-second `min_cluster_seconds` floor means a remote participant who speaks only briefly is likely to be absorbed into another speaker by the local diarizer; this follows from the absorb-small-clusters rule, not from a measured result.
- (Inference) Robustness comes less from the diarization model than from the surrounding rules: channel priors, participant-count bounds, voiceprint-driven merging, refusal to guess when ambiguous, and preserving manual assignments.

## Transcript processing and summarization ("enhance")

### Takeaway
Summarization is a single streamed LLM call per note: the whole speaker-labelled transcript, the user's pre-meeting and in-meeting notes, calendar/participant context and an optional section template are rendered into one system + one user prompt, with length guidance computed from transcript size, early-output validation with retries, then a separate tiny call for the title. There is no chunking/map-reduce and no JSON-schema structured output; output is Markdown. An LLM transcript-correction step (JSON Patch over word ids) exists as a library but I found no caller in the app.

## Comparison with the TinySteno baseline (all judgements are inferences)

### Takeaway
anarlog is clearly ahead on diarization (multi-speaker separation within the remote channel, identity via voiceprints and calendar, echo handling, live operation) and on capture robustness; its summarization is simpler than the baseline in one respect (no chunking, no schema extraction) but richer in context (user notes, participants, templates, validation, streaming).

### Cited Findings
- Baseline description is taken from the assignment brief (TinySteno: stereo WAV, per-channel faster-whisper after the meeting, labels [You]/[Others], chunked JSON extraction per persona schema, merge call, title and tags, Jinja2 Markdown). No external source.
- anarlog evidence used below is cited in the sections above: [pipeline.rs](https://github.com/fastrepl/anarlog/blob/a99e237/crates/pyannote-local/src/pipeline.rs), [diarize.rs](https://github.com/fastrepl/anarlog/blob/a99e237/crates/listener2-core/src/batch/diarize.rs), [consolidate.rs](https://github.com/fastrepl/anarlog/blob/a99e237/crates/listener2-core/src/batch/consolidate.rs), [voiceprint.rs](https://github.com/fastrepl/anarlog/blob/a99e237/plugins/transcription/src/voiceprint.rs), [stream.rs (AEC)](https://github.com/fastrepl/anarlog/blob/a99e237/crates/audio-actual/src/capture/stream.rs), [enhance-workflow.ts](https://github.com/fastrepl/anarlog/blob/a99e237/apps/desktop/src/store/zustand/ai-task/task-configs/enhance-workflow.ts).

### Inferences

Does better (each rests on the code cited above, not on measurements)
- More than two speakers: the remote channel is split into individual speakers (provider diarization or local segmentation + embedding + clustering), bounded by participant count. Baseline has exactly two labels.
- In-person meetings: detects "silent system channel + several expected participants" and diarizes the mic. Baseline would label everyone [You].
- Echo/bleed: neural AEC with reference alignment, disabled on headphones, plus an echo gate for the local live path. Baseline per-channel transcription has no bleed handling, so speaker playback picked up by the mic would be transcribed twice.
- Identity: names from calendar participants (1:1 by elimination), persistent on-device voiceprints with conservative thresholds, automatic self-enrolment when on headphones, manual assignment that survives re-transcription.
- Fusion of channel prior with diarization: the same starting point as the baseline (mic = me, system = others) is kept as a hard prior and diarization is applied only where it adds information (skip 1:1 remote channel, never diarize an isolated mic). This avoids diarization errors in the easy cases.
- Live transcript with post-meeting refinement, reconnect replay, dropout detection.
- Summaries use the user's own notes with explicit pre/post-meeting diffing and emphasis cues, participant list, user-editable templates, length scaled to transcript size, dictionary terms, streaming, and early-output validation with retry.
- Engineering safeguards worth noting: word-count/id-preserving LLM correction contract; truncation guards when replacing a transcript; DER eval harness with a keep/revert rule.

Does worse or not at all
- No chunking or map-reduce for long transcripts; depends on the model's context window. The baseline's chunk-extract-merge is more robust for small local models. Evidence: single-call workflow.
- No schema-constrained structured output; fields are Markdown sections, validated only at the first heading. The baseline's per-persona JSON schema gives typed, template-renderable fields.
- Tags are regex-extracted hashtags, not generated. Baseline generates tags with the LLM.
- Local, fully offline operation is effectively Apple-Silicon-only for ASR and diarization; the baseline's faster-whisper path is cross-platform and GPU-capable.
- Far heavier: a Tauri GUI monorepo with bundled ONNX models (segmentation 6 MB, embedding 26.5 MB, AEC, VAD) versus a Python CLI.
- Local diarization absorbs clusters with under 12 s of anchor speech, so brief speakers can be lost; Soniqo diarization input is capped at 10 minutes of audio per call.
- Still has open channel-interleaving and provider-specific speaker bugs (PRs #8189, #8192, #8127), which shows that word-level merging of two channels is harder than per-channel blocks.

Techniques that look adoptable by a Python CLI (inference; feasibility not tested)
- Keep the channel prior, and run a pyannote-style diarizer only on the system-audio channel, and only when expected remote participants > 1; pass participant count as min/max speaker bounds.
- Detect the in-person case from a near-silent system channel and diarize the mic instead.
- Cross-channel echo gate (correlate mic against system audio, drop mic segments dominated by it) as a cheap alternative to full AEC; skip when headphones are used.
- Assign words to speakers by maximum time overlap with nearest-turn fallback.
